## 왜 SLUR인가?

- 클래스 네이밍 기준이 사람마다 다릅니다.
- 스타일 수정이 구조 수정으로 이어집니다.
- 로딩·에러 같은 상태, 접근성, 성능이 매번 설계에서 빠집니다.
- 프로젝트가 커질수록 유지보수가 어려워집니다.

## 접두사 하나로 구조가 읽힙니다

블록과 내부 요소를 접두사로 구분해, 클래스 이름만으로 구조 범위를 판단할 수 있습니다.

```html
<article class="card_product" data-state="loading">
  <div class="i_body">
    <h3 class="i_title">상품명</h3>
  </div>
  <button class="btn m_primary">담기</button>
</article>
```

`page_`·`p_` / `layout_`·`l_` / `modal_` / `i_` / `m_` / `data-state` — 전체 기준은 [접두사 참조 표](/reference/prefix-table/)에서 확인합니다.

## 이런 분들을 위한 문서입니다

- 프론트엔드 개발자 / 퍼블리셔
- CSS 구조와 네이밍에 고민이 있는 분
- 디자인 시스템 또는 UI 가이드를 만들고 싶은 팀
- 1회성이 아닌 운영 가능한 UI를 만들고 싶은 실무자

---

## SLUR UX/UI System은 프레임워크가 아닙니다

특정 기술이나 라이브러리에 종속되지 않는  
**UI 설계 기준이자 문서화 방법론**입니다.

어떤 환경에서도 적용할 수 있습니다.
