---

SRR 방법론은 UI를 안정적으로 유지하기 위해  
각 기술 요소의 역할과 책임을 명확하게 분리합니다.  
역할 분리는 코드 구조를 단순하게 만들고,  
변경 범위를 예측 가능하게 하기 위한 핵심 원칙입니다.

---

## 역할 분리의 목적

역할 분리 원칙은 다음과 같은 목적을 가집니다.

- 코드 간 의존성을 최소화합니다.
- 수정 시 영향을 받는 범위를 명확히 합니다.
- CSS와 JavaScript의 책임 충돌을 방지합니다.
- UI 구조를 장기적으로 안정화합니다.

SRR는 하나의 요소가 여러 책임을 가지는 구조를 지양합니다.

---

## CSS의 역할

CSS는 **구조와 표현을 정의**하는 역할만 담당합니다.

- UI 구조를 시각적으로 표현합니다.
- 상태에 따른 스타일 변화를 담당합니다.
- 레이아웃, 간격, 색상, 타이포그래피를 관리합니다.

CSS는 다음 역할을 수행하지 않습니다.

- 상태 판단
- 데이터 처리
- 이벤트 제어

CSS는 항상 **결과 기반 CSS 원칙**을 따릅니다.

---

## JavaScript의 역할

JavaScript는 **행동과 상태 제어**를 담당합니다.

- 사용자 입력 처리
- UI 상태 변경
- 이벤트 흐름 제어
- 외부 라이브러리 연동

JavaScript는 다음 역할을 수행하지 않습니다.

- 시각적 스타일 정의
- 구조 변경을 위한 임의의 클래스 조작

JavaScript는 UI 구조를 직접 변경하지 않고,  
정해진 규칙을 통해 상태만 제어합니다.

---

## 데이터 속성의 역할

데이터 속성(`data-*`)은  
CSS와 JavaScript를 연결하는 **중립적인 상태 전달 수단**으로 사용합니다.

- UI 상태 표현
- 역할 식별
- 스크립트 제어 대상 지정

데이터 속성은 다음 원칙을 따릅니다.

- 구조를 변경하지 않습니다.
- 스타일을 직접 표현하지 않습니다.
- 상태와 역할 전달에만 사용합니다.

데이터 속성은 클래스 네이밍을 대체하지 않습니다.

---

## 역할 분리 기준 요약

SRR의 역할 분리 기준은 다음과 같습니다.

- CSS는 **보이게 하는 역할**만 담당합니다.
- JavaScript는 **동작과 상태 제어**만 담당합니다.
- 데이터 속성은 **상태 전달과 연결**만 담당합니다.

이 세 역할은 서로의 영역을 침범하지 않아야 하며,  
각각 독립적으로 관리될 수 있어야 합니다.

---

## 역할 분리 원칙의 효과

이 원칙을 따르면 다음과 같은 효과를 얻을 수 있습니다.

- 구조 변경 없이 스타일 수정이 가능합니다.
- 스크립트 수정이 UI 구조에 영향을 주지 않습니다.
- 코드 리뷰와 유지보수가 쉬워집니다.
- 대규모 UI에서도 안정성을 유지할 수 있습니다.

역할 분리 원칙은  
SRR 방법론 전반을 지탱하는 기본 설계 기준입니다.
