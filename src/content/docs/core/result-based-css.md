SRR 방법론은 CSS를 작성할 때  
개발 도구나 작성 방식이 아닌 **빌드 이후 생성되는 최종 결과물**을 기준으로 판단합니다.  
이를 통해 도구 종속성을 줄이고, 일관된 UI 구조를 유지하도록 설계했습니다.

---

## 결과 기반 CSS의 개념

결과 기반 CSS는  
SCSS, PostCSS, 빌드 도구와 같은 구현 수단이 아니라  
**서버에 배포되는 최종 CSS 결과물**을 기준으로 UI를 설계하는 접근 방식입니다.

- 개발 과정은 자유롭게 선택할 수 있습니다.
- 판단 기준은 항상 동일해야 합니다.
- 결과물이 명확하면 구조도 명확해집니다.

---

## 왜 결과물을 기준으로 하는가

SRR가 결과물을 기준으로 삼는 이유는 다음과 같습니다.

- 빌드 도구는 프로젝트마다 달라질 수 있습니다.
- 작성 방식이 달라도 결과 CSS는 동일해야 합니다.
- 유지보수 시 참고 대상은 항상 배포된 코드입니다.
- 도구 변경이 UI 구조 변경으로 이어지지 않도록 하기 위함입니다.

SRR는 **도구가 바뀌어도 구조는 유지되는 CSS**를 목표로 합니다.

---

## 적용 기준

결과 기반 CSS는 다음 기준을 따릅니다.

- 모든 규칙은 최종 CSS 기준으로 설명합니다.
- 중첩, 변수, 믹스인은 결과물에 영향을 주지 않는 선에서만 사용합니다.
- 소스 코드가 아닌 결과 CSS를 기준으로 구조를 검토합니다.
- 디버깅과 유지보수는 결과 CSS를 중심으로 진행합니다.

이 기준은 SRR의 모든 CSS 규칙에 공통으로 적용됩니다.

---

## 결과 기반 CSS의 특징

SRR의 결과 기반 CSS는 다음과 같은 특징을 가집니다.

- 특정 전처리기나 프레임워크에 종속되지 않습니다.
- 코드 리뷰와 구조 검토 기준이 명확해집니다.
- 팀 간 협업 시 동일한 판단 기준을 유지할 수 있습니다.
- 장기 유지보수 시 구조 파악이 용이합니다.

결과 기반 CSS는  
SRR 방법론에서 구조 중심 사고를 실제 코드로 연결하는 핵심 원칙입니다.
