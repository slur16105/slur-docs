처음 접하는 사람부터 실무에 바로 적용하려는 UI 개발자까지 모두를 고려해 구성되었습니다.  
이 문서는 SLUR UX/UI System의 철학과 규칙을 단계적으로 이해하고, 필요한 내용을 빠르게 찾아볼 수 있도록 설계되었습니다.

---

## 문서 구성 안내

해당 문서는 다음과 같은 흐름으로 구성되어 있습니다.

- 배경과 철학을 설명하는 **시작 안내**
- UI 구조 설계를 이해하기 위한 공통 기준을 다루는 **핵심 개념**
- 실제 규칙과 적용 기준을 설명하는 **방법론 가이드**
- 실무 적용 예제와 기준을 제공하는 **패턴 / 참고 자료**

각 문서는 독립적으로 읽을 수 있도록 작성되었지만, 순서대로 읽을 경우 전체 구조와 의도를 더 명확하게 이해할 수 있습니다.

---

## 권장 읽기 순서

처음 접하는 경우 다음 순서로 읽는 것을 권장합니다.

1. **SLUR UX/UI System 개요**  
   개념과 목적을 이해합니다.

2. **설계 철학**  
   어떤 관점으로 UI를 바라보는지 확인합니다.

3. **왜 SLUR UX/UI System인가**  
   기존 UI 개발의 문제점과 SLUR UX/UI System이 해결하는 범위를 이해합니다.

4. **핵심 개념**  
   UI 구조, 네이밍 규칙, 역할 분리 기준을 학습합니다.

5. **CSS / JavaScript / 접근성 가이드**  
   실무에 적용 가능한 구체적인 규칙과 기준을 확인합니다.

---

## 필요한 내용만 빠르게 확인하는 방법

해당 문서는 참고 문서로도 활용할 수 있도록 구성되었습니다.

- 네이밍 규칙이나 접두사 기준이 필요한 경우  
  → **참고 자료** 섹션을 확인합니다.

- UI 구조 패턴이나 실무 예제가 필요한 경우  
  → **패턴** 섹션을 참고합니다.

- 접근성, 성능, 이미지 처리 기준이 필요한 경우  
  → 각 전용 가이드를 바로 확인합니다.

모든 문서는 주제별로 명확하게 분리되어 있어, 필요한 규칙을 빠르게 찾을 수 있도록 구성되었습니다.

---

## 문서를 읽을 때의 기준

문서는 다음과 같은 기준을 바탕으로 작성되었습니다.

- 특정 프레임워크나 빌드 도구에 종속되지 않습니다.
- 예제 코드는 원리를 설명하기 위한 최소한의 형태로 제공됩니다.
- 모든 규칙은 빌드 이후 결과물을 기준으로 설명합니다.
- “어떻게 사용하는가”보다 “왜 이 규칙이 필요한가”를 우선 설명합니다.

이를 통해 이 문서는 단순한 사용 설명서가 아닌, UI 구조를 설계하기 위한 기준 문서로 활용될 수 있도록 구성되었습니다.
