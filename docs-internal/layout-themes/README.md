# 레이아웃 테마 실험 기준

레이아웃 테마는 색상이나 외형을 바꾸지 않고 화면의 여백, 정보 밀도, 열 구성과 메뉴 위치를 조절한다. 유형 하나는 CSS 파일 하나이며 `base.css`가 역할 토큰과 구조별 배치를 기존 실험실 HTML에 연결한다. 기존 구조의 변형은 테마 파일과 HTML 선택지·링크 등록으로 추가한다. 새로운 구조를 도입할 때는 공통 어댑터와 검사 기준도 확장해야 한다.

## 현재 레이아웃

- `comfortable.css`: 균형 잡힌 기본 여백과 배치
- `compact.css`: 좁은 여백과 높은 정보 밀도
- `spacious.css`: 넓은 여백과 단순한 콘텐츠 열
- `split.css`: 왼쪽 포커스·차트·프로젝트, 오른쪽 지표·활동. 작업 영역이 800px 미만이면 원래 순서의 세로 배치로 돌아온다.
- `top-nav.css`: 같은 메뉴를 상단으로 옮겨 본문 전체 폭을 활용한다. 모바일에서는 메뉴를 3열로 줄바꿈한다.
- `focus.css`: 제목과 본문을 최대 820px 읽기 폭으로 중앙 정렬하고 주요 섹션을 세로로 배치한다.
- `board.css`: 프로젝트 목록을 실제 가용 폭에 따라 1~3열 카드로 표시한다. 720px 이하에서는 한 열이며 상태·진행률·참여자를 유지한다. 드래그나 상태 이동 기능이 없는 배치 실험이다.

## 승인 조건

- 각 파일은 자신의 `data-layout-theme` 선택자와 승인된 `--layout-*` 토큰만 선언한다.
- 구조별 추가 필수 토큰은 Split의 `--layout-split-columns`, Focus의 `--layout-reading-width`, Board의 `--layout-board-card-min-width`이다. 구조별 CSS는 `base.css`에서만 관리하고, 새 구조 토큰은 검사 스크립트에 등록한다.
- 컬러값, 외형 토큰, 일반 CSS 속성, `@import`, `!important`, URL은 넣지 않는다.
- 720px 이하에서는 본문을 공통 한 열로 유지해 가로 스크롤과 터치 영역 회귀를 방지한다. Top Nav의 메뉴는 숨기지 않고 텍스트와 함께 줄바꿈하며 44px 높이를 유지한다.
- 721~1100px에서 세로 메뉴 레이아웃은 공통 아이콘 레일 너비에 맞춘다. Top Nav는 상단 메뉴 이름을 그대로 표시한다. 두 경우 모두 메뉴 이름은 보조 기술에서 읽을 수 있어야 한다.
- Split은 DOM 복제·재정렬 없이 행별 읽기 순서(포커스→지표→차트→활동→프로젝트)를 유지한다. 의미 없는 `p_grid` 래퍼만 `display:contents`로 처리한다. 프로젝트 행은 전체 본문이 아니라 실제 패널 너비로 접는다.
- Board도 프로젝트 노드를 복제하거나 재정렬하지 않는다. 카드 안에서 이름→상태→진행률→참여자→동작의 DOM 읽기 순서를 유지하고, 다른 레이아웃으로 전환하면 기존 행 배치로 돌아온다.
- 콘텐츠가 좁아지면 컨테이너 쿼리로 포커스 카드·지표·프로젝트 행을 접는다. 상태 배지는 텍스트 길이에 맞춰 표시하며 모바일에서도 다음 줄에 유지한다.
- `npm run check:themes`와 `npm run build`를 통과한 다음 Git에 기록한다.

브라우저에서는 320px, 720px 전후, 1100px 전후와 Split의 작업 영역 800px 전후를 확인한다. 문서 전체뿐 아니라 카드 내부 넘침, 배지 줄바꿈, 메뉴의 실제 표시 여부, Tab 이동과 기존 레이아웃 복귀를 함께 검사한다.

자동 검사는 토큰 규칙과 색 대비를 확인한다. 총 조합 수는 선택 가능한 조합의 개수이며, 모든 화면의 렌더링 또는 WCAG 전체 항목을 검사했다는 의미는 아니다. 승인 전 실제 브라우저에서 좁은 화면·분기점 전후·포커스를 별도로 확인한다.
