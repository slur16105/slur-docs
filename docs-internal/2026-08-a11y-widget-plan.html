슬러 시스템 「복합 위젯 접근성 기준」 수립 계획

작성일: 2026-08-21 · 상태: 검토 대기 (레포는 아직 아무것도 수정하지 않음) 성격: 내부 결정 기록. 공개 문서(docs/스킬)에는 이 문서의 5장(타사 비교)을 옮기지 않는다.

0. 한 줄 결론과 원칙

웹 접근성 공식 표준(W3C APG · WCAG 2.2 · KWCAG 2.2)을 근거로, 슬러 방식(구조 우선 · data-state · 최소 ARIA · 네이티브 우선)으로 "복합 위젯이 어떻게 움직여야 하는가"의 우리 기준을 세운다.

지키는 원칙 4가지:

  1. 근거는 표준으로만 댄다. 규칙마다 APG 패턴 + WCAG 기준 번호 + KWCAG 항목을 붙인다.
  2. 네이티브 우선. 브라우저가 기본 제공하는 것(<dialog>, popover, inert)을 1순위로, JS 구현은 그게 안 될 때의 대안으로 둔다. 이게 "구조가 명확하면 접근성은 따라온다"는 슬러 철학과 같은 방향이다.
  3. 남과 비교하지 않는다. 라이브러리(Radix·React Aria·Ark 등)는 "표준을 구현한 사례"로 내부 기록에서만 참고한다. 공개 문서에는 "~보다 낫다/~는 못한다" 문장을 0건으로 하고, 라이브러리 이름은 독자에게 실익이 있는 중립 정보(예: data-state 호환)일 때만 쓴다.
  4. 복잡한 위젯은 규칙화하지 않고 위임한다. 셀렉트·콤보박스·날짜선택기는 네이티브 → 헤드리스 라이브러리 순으로 맡기고, 슬러는 구조·네이밍·data-state만 얹는다.

1. 근거로 삼는 공식 문서와 각각의 역할

문서 발행 역할 우리가 가져오는 것
WAI-ARIA APG (Authoring Practices Guide) W3C (Note, 권장 관행) "어떻게 움직여야 하나" — 위젯별 키보드·포커스·ARIA 패턴 다이얼로그·탭·메뉴·알림 패턴의 키 동작, roving tabindex 알고리즘, 초기 포커스 규칙

MDN + web-features/caniuse Mozilla / 커뮤니티 플랫폼 사실 — 속성·API 동작과 브라우저 지원 <dialog>, popover, inert, command/commandfor, live region 동작

역할이 다르므로 인용도 나눈다: 동작은 APG, 기준은 WCAG/KWCAG, 사실은 MDN.

나라별 차이는 어디까지인가

  • 위젯 동작 규칙(이번에 정하는 것)은 국제 공통. 스크린리더·브라우저가 같으므로 나라별로 달라질 이유가 없고, 모두 APG 하나를 본다.
  • 성공 기준도 거의 같다. 대부분 나라가 WCAG를 채택·번역하며, KWCAG 2.2도 WCAG 2.1/2.2 대응이다.
  • 다른 것은 법적 범위·버전·레벨·인증 제도뿐이다 (미국 Section 508/ADA, EU EN 301 549/EAA, 영국 공공부문 규정, 일본 JIS X 8341-3, 한국 KWCAG + 품질인증 등).
  • 슬러의 입장: 방법론이 법규를 다룰 일은 아니므로 공개 문서에는 "WCAG 2.2 AA · KWCAG 2.2를 목표 기준으로 한다" 한 줄만 선언하고, 규칙마다 WCAG 번호 + KWCAG 항목을 병기해 국내 인증·감리 때 바로 매핑되게 한다. 나라별 법규 표는 넣지 않는다.

2. 슬러 시스템의 현재 상태

skill/slur-ux/references/와 src/content/docs/a11y/를 읽어 확인했다.

이미 있는 것: alt 역할별 작성 · 시맨틱 우선·role 중복 금지 · div[role=button] 금지 · DOM 순서 = 포커스 순서 · 양수 tabindex 금지 · :focus-visible · Enter/Space/Esc 기본 동작 · 제목 구조 · a11y_hidden 표준 구현 · 로고 마크업 · 아코디언 aria-expanded 예시 · 모달 role="dialog" aria-modal aria-labelledby 예시 + 열릴 때 i_close로 포커스 + Esc · 탭 role="tab"/aria-selected 마크업 · 토스트 aria-live 예시 · 외부 라이브러리는 상태 트리거만 맡는다는 원칙.

없는 것: 위젯의 동작 규칙 — 포커스 트랩/복귀, 방향키 이동(roving tabindex), 알림을 읽어주는 기준(status/alert), 닫기 규칙(바깥 클릭·겹침), 툴팁, 복잡 위젯 위임 원칙, 네이티브 <dialog>/popover/inert 활용 지침.

발견된 불일치: 토스트 마크업이 component.md는 role="alert" aria-live="polite"(모순), ux-states.md는 role="status" → 통일 필요.

3. 플랫폼 현황 (2026-08 검증) — "네이티브 우선"이 가능한가

기능 하는 일 지원 (2026-08) 슬러 판단
<dialog> + showModal() 최상위 레이어 표시, 배경 전체 자동 inert, Esc로 닫힘, 닫힐 때 이전 포커스로 복귀(스펙), 초기 포커스 = 첫 포커스 가능 요소(autofocus 우선) Chrome 37 / Firefox 98 / Safari 15.4, 전역 96% (Baseline 2022) 채택 — 모달의 1순위
inert 속성 붙은 요소 안의 포커스·클릭·선택·보조기술 읽기를 모두 차단 Chrome 102 / Firefox 112 / Safari 15.5, 전역 95% (Baseline 2023) 채택 — 커스텀 오버레이의 배경 차단
popover="auto" 최상위 레이어, Esc + 바깥 클릭 light-dismiss, 키보드로 닫으면 호출 버튼으로 복귀, 포커스는 가두지 않음 Chrome 114 / Firefox 125 / Safari 17, 전역 91% (Baseline 2024) 채택 — 드롭다운·팝오버·비모달 레이어
command="show-modal" + commandfor JS 없이 버튼으로 dialog/popover 열고 닫기 Chrome 135 / Firefox 144 / Safari 26.2, 전역 ~83% 채택 가능 — 단 JS 폴백 설명 필요
<dialog closedby="any"> dialog에도 바깥 클릭 닫기 Chrome 134 / Firefox 141 / Safari 미지원 향상 전용(있으면 좋고 없어도 됨)
popover="hint" 툴팁용 팝오버 Safari 미지원(미지원 시 manual로 폴백되어 light-dismiss 사라짐) 아직 쓰지 않음
appearance: base-select 네이티브 <select>를 CSS로 스타일링 Chrome 135 / Safari 27 예정 / Firefox 미지원 향상 전용

중요한 정정 하나: <dialog>는 포커스를 "가두지" 않는다. 배경이 inert라 Tab이 페이지로 새지 않을 뿐, 브라우저 주소창으로는 나갈 수 있고 W3C APA WG는 이를 정상으로 결론냈다. 그러므로 슬러 규칙은 "포커스를 가둔다"가 아니라 "모달이 열린 동안 페이지 콘텐츠로 포커스가 새지 않는다" 로 쓴다. 네이티브는 자동으로 만족하고, 커스텀 div[role=dialog]는 inert + Tab 순환으로 만족시킨다.

4. 슬러가 세우는 기준 (이 문장들이 스킬·문서에 들어간다)

4-0. 복합 위젯 판정

다음 중 하나라도 해당하면 복합 위젯이다.

  1. 열린 동안 페이지로 포커스가 새면 안 된다 (모달·드로어) → A
  2. 그룹 안을 방향키로 움직인다 (탭·메뉴·라디오 그룹) → B
  3. 화면 변화를 보조 기술에 알려야 한다 (토스트·로딩/에러 전환) → C

떠 있는 레이어는 닫기 규칙(D), 툴팁은 E, 셀렉트·콤보박스처럼 복잡하면 위임(F).

A. 모달·드로어 — 포커스 관리

규칙

  1. 네이티브 <dialog> + showModal()을 1순위로 쓴다. 배경 inert·Esc·포커스 복귀가 기본 제공된다.
  2. 커스텀 오버레이(div[role=dialog] aria-modal)를 써야 하면 (a) 열린 동안 배경에 inert 를 붙이고 (b) Tab/Shift+Tab이 오버레이 안에서 순환하게 한다.
  3. 초기 포커스 = 오버레이 안 첫 포커스 가능 요소. 예외 3가지: 긴 본문이면 시작부 제목(tabindex="-1"), 삭제·결제처럼 되돌릴 수 없는 확인이면 덜 파괴적인 버튼(취소), 상호작용 요소가 없으면 오버레이 자체.
  4. 닫히면 포커스는 연 버튼으로 복귀한다. 연 버튼이 사라졌으면 문맥상 다음 위치로.
  5. 스크롤 잠금은 기존대로 body[data-state="modal_open"].

근거: APG Dialog(Modal) 패턴 · WCAG 2.1.2(키보드 함정 없음) 2.4.3(포커스 순서) 2.4.7(포커스 표시) 1.3.1(정보와 관계) · KWCAG 6.1.1 키보드 사용 보장, 6.1.2 초점 이동과 표시 · NIA 제작기법 2.1.2("첫 상호작용 요소로, 닫힐 땐 열었던 버튼으로").

슬러식 적용: 구조(modal_* + i_wrap/i_head/i_close)와 data-state="open|close"는 그대로. 네이티브 예시는 <dialog class="modal_login">로 바꾸고 open()/close()가 showModal()/close()를 부르며 data-state를 동기화. 커스텀 예시는 트리거 기억 → 복귀, inert 토글, 순환 핸들러 ≈15줄.

B. 방향키로 움직이는 위젯 (탭 · 메뉴 · 라디오 그룹)

규칙

  1. Tab은 위젯 사이를, 방향키는 위젯 안을 움직인다. 탭 5개면 Tab 한 번에 그룹을 통째로 지난다.
  2. roving tabindex: 현재 항목만 tabindex="0", 나머지 -1. 방향키로 이동하면 tabindex·data-state="active"·aria-selected를 함께 갱신한다. Home/End 는 처음/끝.
  3. 탭 활성화 기본값 = 자동(포커스가 가면 패널 전환). 단 패널이 비동기 로드라 느리면 수동(Enter/Space로 전환).
  4. 사이트 내비게이션은 방향키 위젯이 아니다. nav > ul > li > a는 role="menu"를 쓰지 않고 그냥 Tab으로 간다. menu 롤은 앱의 동작 메뉴(편집·공유 등)에만 쓴다 — 가장 흔한 남용이라 명시한다.

근거: APG Tabs 패턴("패널 지연이 없으면 자동 활성화 권장") · APG Keyboard Interface(roving tabindex 알고리즘) · APG Disclosure 예제(내비게이션에 menu 비권장) · WCAG 2.1.1, 2.4.3 · KWCAG 6.1.1, 6.1.2 · NIA 제작기법 2.1.1(탭은 리스트 안 화살표, Tab으로 패널).

슬러식 적용: component.md 탭 예시에 tabindex 추가, 방향키 핸들러 예시 ≈15줄(data-state만 토글). "그룹 안 하나만 선택되는가?" 판정 문장 한 줄.

C. 상태 변화를 보조 기술에 알리기 (라이브 영역)

규칙

  1. 토스트·상태 메시지의 기본은 role="status" (+ 호환성 위해 aria-live="polite" 병기). 끼어들어야 하는 실패·세션 만료·시간 제한만 role="alert".
  2. 라이브 영역 컨테이너는 미리 DOM에 있어야 읽힌다. 슬러의 "4상태를 마크업에 미리 둔다" 원칙과 같다.
  3. 알림은 포커스를 옮기지 않는다.
  4. role="alert" 메시지는 자동으로 사라지지 않는다. status 토스트는 자동 소멸을 허용하되, 같은 정보를 다른 곳에서 다시 확인할 수 있어야 한다.

근거: APG Alert 패턴(포커스 이동 금지·자동 소멸 금지) · MDN Live regions(status=polite, alert=assertive, 선존재) · WCAG 4.1.3(상태 메시지) 2.2.1(시간 조절) · KWCAG 8.2.1 웹 애플리케이션 접근성 준수, 6.2.2 정지 기능 제공 ※KWCAG 매핑은 작성 단계에서 원문 대조.

슬러식 적용: 토스트 마크업을 role="status"로 통일(현재 불일치 해소). ux-states.md 피드백 선택 표에 "알림 강도(status/alert)" 열 추가. i_loading/i_error 영역도 같은 방식으로 알릴 수 있음을 한 줄.

D. 떠 있는 레이어의 닫기 규칙

규칙

  1. 모달·드로어·드롭다운·팝오버는 Esc로 닫힌다. 비모달 레이어(드롭다운·팝오버)는 바깥 클릭으로도 닫힌다 — popover="auto"를 쓰면 기본 제공.
  2. 파괴적 확인 모달은 바깥 클릭으로 닫지 않는다(실수 방지). Esc는 "취소"와 같은 의미로 허용.
  3. 여러 레이어가 겹치면 Esc는 맨 위 하나만 닫는다.
  4. 떠 있는 레이어가 포커스된 요소를 완전히 가리면 안 된다(스티키 토스트 주의).

근거: WCAG 1.4.13(호버·포커스 콘텐츠는 해제 가능) 2.4.11(포커스 가림 없음) · APG Dialog/Menu(Esc) · MDN Popover API(light-dismiss). 코드 예시 없이 규칙만.

E. 툴팁

규칙: 호버와 포커스 모두에서 뜨고, Esc로 포커스 이동 없이 닫히며, 마우스를 툴팁 위로 옮겨도 유지된다. 연결은 aria-describedby(설명) 또는 aria-labelledby(라벨). 툴팁 안에 버튼·링크를 넣지 않는다 — 그건 팝오버/다이얼로그다.

근거: WCAG 1.4.13 (APG 툴팁 패턴은 "합의 미완" 표기라 주 근거로 쓰지 않음). 한 문단, 예시 없음.

F. 복잡 위젯은 규칙화하지 않고 위임

규칙: 셀렉트는 네이티브 <select> 를 먼저 쓴다(스타일은 appearance: base-select로 점진 향상). 커스텀 콤보박스·날짜선택기·메뉴바가 꼭 필요하면 헤드리스 라이브러리(프레임워크 무관이면 Zag/Ark UI, React면 React Aria 등)에 동작을 맡기고, 슬러는 구조·네이밍·data-state만 얹는다. 이미 있는 「외부 라이브러리 연동」 원칙(라이브러리는 상태 트리거일 뿐)과 같은 선상이다.

근거(내부용): 콤보박스의 aria-activedescendant는 스크린리더별 지원 편차가 커서 직접 구현 시 검증 부담이 크다(Adobe React Aria 콤보박스 구현기). 공개 문서에는 "검증된 라이브러리에 맡긴다"로만 쓴다.

G. 이번 범위 밖 (보류, 다음 후보)

prefers-reduced-motion, 색 대비 비율(WCAG 1.4.3/1.4.11), 터치 타깃 24px(WCAG 2.5.8 / KWCAG 6.1.3), 문자 단축키(2.1.4 / KWCAG 6.1.4), 접근 가능한 인증(3.3.8 / KWCAG 7.3.3). 중요하지만 "위젯 동작"이 아니므로 섞지 않는다.

5. 남들은 어떻게 했나 — 내부 참고 (공개 문서에 옮기지 않음)

같은 표준을 보고도 구현체마다 해석이 갈리는 지점과, 우리가 고른 기본값·이유.

쟁점 갈린 입장 슬러 기본값 이유
다이얼로그 초기 포커스 첫 포커스 가능 요소(APG·네이티브 <dialog>·NIA·Base UI) ↔ 다이얼로그 자체(Headless UI) ↔ 유형별 주 버튼/취소(Carbon) 첫 포커스 가능 요소 + APG 예외 3종 표준·네이티브·국내 기법이 일치. 파괴적 확인은 예외로 "취소"를 잡아 Carbon의 장점도 흡수
포커스 "트랩" Tab 순환 트랩(APG·USWDS·React Aria) ↔ 배경 inert면 충분(네이티브 showModal()·W3C APA WG) 네이티브는 트랩 없음, 커스텀은 inert + 순환 두 갈래를 그대로 서술 — 플랫폼 사실에 맞춤
탭 활성화 자동(APG·React Aria·Headless UI·Zag) ↔ 수동 기본(Base UI) 자동, 비동기 패널은 수동 APG 원문 기준
토스트 롤 status 기본(Inclusive Components·MDN) ↔ 시간 민감하면 alert·자동 소멸 금지(APG) status 기본 + alert는 긴급·비소멸 둘을 역할로 나누면 충돌 없음
내비게이션에 menu 롤 금지/비권장(Inclusive Components·APG Disclosure 예제) ↔ APG Menubar에 내비게이션 예제 존재 사이트 내비는 nav+리스트, menu는 앱 메뉴만 슬러의 시맨틱 우선·최소 ARIA와 일치
문서 형식 USWDS: 테스트 문장 + WCAG 번호 표 / GOV.UK: 수용 기준 / Carbon: 테스트 상태 체크리스트를 "테스트 문장 + WCAG·KWCAG 번호"로 형식 차용은 비교가 아니고 독자 실익

참고한 구현체(상태 2026-08): React Aria Components 1.20(활발), Zag.js 1.43/Ark UI 5.38(활발, 프레임워크 무관), Base UI 1.7(2025-12 안정화), Headless UI(React 유지보수 위주·Vue 정체), Radix Primitives. 이들은 모두 "APG를 구현했다"고 선언하며, 상태를 data-state로 노출하는 경우가 많아 슬러 네이밍을 얹기 쉽다 — 공개 문서에 쓸 수 있는 유일한 라이브러리 언급은 이 호환 정보뿐이다.

부록 A — 용어집

  • 포커스 트랩 / 순환: 오버레이가 열린 동안 Tab이 안에서만 도는 것. 슬러 문장은 "페이지로 포커스가 새지 않는다".
  • 포커스 복귀: 닫았을 때 포커스가 연 버튼으로 돌아가는 것.
  • roving tabindex: 그룹 안에서 하나만 tabindex="0", 나머지 -1로 두고 방향키로 0을 옮기는 기법. Tab 한 번에 그룹을 건너뛰게 해 준다.
  • inert: 붙은 요소 안의 클릭·포커스·스크린리더 읽기를 전부 막는 HTML 속성. aria-hidden은 읽기만 막고 포커스는 못 막는다.
  • 라이브 영역: 내용이 바뀌면 스크린리더가 자동으로 읽는 영역. status(조용히, 읽던 것 끝나고) / alert(즉시 끼어듦).
  • light-dismiss: Esc나 바깥 클릭으로 닫히는 것. popover="auto"가 기본 제공.
  • 헤드리스 라이브러리: 스타일 없이 동작(키보드·ARIA)만 주는 라이브러리. 슬러 네이밍을 그대로 얹을 수 있다.
  • APG / WCAG / KWCAG: 동작 관행(W3C Note) / 국제 표준(W3C Recommendation) / 한국 지침(KS 표준, 국내 인증 기준).
