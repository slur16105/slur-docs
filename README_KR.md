# SRR (Structure · Rule · Role)

**SRR**은 UI 마크업과 CSS 설계를  
**구조(Structure)** · **규칙(Rule)** · **역할(Role)** 관점에서 정리한  
UI 구조 설계 방법론입니다.

이 저장소는 SRR 방법론을 설명하고,  
실무에서 바로 참고할 수 있도록 정리된 **공식 문서 레퍼런스**입니다.

---

## SRR이 필요한 이유

많은 UI 프로젝트에서 다음과 같은 문제가 반복됩니다.

- 클래스 네이밍 기준이 사람마다 다름
- 스타일 수정이 구조 수정으로 이어짐
- 디자이너와 개발자 간 UI 해석 불일치
- 프로젝트 규모가 커질수록 유지보수 난이도 증가

SRR은 UI를 단순한 결과물이 아니라  
**구조화된 시스템**으로 다루기 위해 만들어졌습니다.

---

## SRR의 핵심 개념

### 1. Structure (구조)
- 레이아웃, 페이지, 컴포넌트 단위를 명확히 분리
- DOM 구조만 봐도 UI 의도가 드러나도록 설계
- 스타일 변경에도 구조가 흔들리지 않도록 설계 기준 제공

### 2. Rule (규칙)
- 클래스 네이밍 규칙 정의
- 블록 / 내부 요소 / 수정자 관계 명확화
- 가상 요소, Data Attribute 사용 원칙 정리
- 프로젝트 전반에 일관된 작성 기준 유지

### 3. Role (역할)
- 각 요소가 담당하는 역할 중심의 설계
- 장식용 요소와 의미·기능 요소의 구분
- 접근성, 협업, 유지보수를 고려한 역할 정의
