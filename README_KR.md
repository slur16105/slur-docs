# SLUR UX/UI System

[![Docs](https://img.shields.io/badge/docs-docs.slur.co.kr-blue)](https://docs.slur.co.kr)
![Status](https://img.shields.io/badge/status-active-success)
![Methodology](https://img.shields.io/badge/type-UX%2FUI%20Methodology-informational)

**SLUR UX/UI System**은 한 번 구조화한 UI를 오래 유지하도록 설계하는
프론트엔드 UX/UI 방법론입니다. **구조·상태·접근성·성능·경험**까지
하나의 기준으로 이어서, 클래스 이름만 봐도 구조와 역할이 읽히며
특정 프레임워크에 종속되지 않습니다.

이 저장소는 해당 시스템의 **공식 문서**이며,
[docs.slur.co.kr](https://docs.slur.co.kr)에 배포되어 있습니다.

---

## SLUR UX/UI System이 필요한 이유

많은 UI 프로젝트에서 다음과 같은 문제가 반복됩니다.

- 클래스 네이밍 기준이 사람마다 다름
- 스타일 수정이 구조 수정으로 이어짐
- 디자이너와 개발자 간 UI 해석 불일치
- 프로젝트 규모가 커질수록 유지보수 난이도 증가

SLUR은 UI를 단순한 결과물이 아니라 **구조화된 시스템**으로 다루며,
이 원칙을 마크업을 넘어 상태·접근성·미디어·사용자 경험까지 확장합니다.

---

## 핵심 원칙

- **구조 우선** — 클래스 이름만 봐도 구조와 역할이 읽히도록 설계합니다. UI를 스타일의 집합이 아닌 안정적인 구조로 다룹니다.
- **역할 분리** — 구조는 HTML, 표현은 CSS, 동작은 JavaScript, 상태는 `data-state`가 담당합니다.
- **일관된 규칙** — 누가 작성해도 같은 구조로 읽힙니다. 일관성이 생산성을 만듭니다.
- **완결성** — 정상 상태만이 아니라 로딩·에러 상태, 접근성, 성능까지 처음부터 설계합니다.

---

## 다루는 범위

구조 설계에서 끝나지 않고, 모든 영역을 하나의 기준으로 이어갑니다.

- **구조 · 네이밍** — 블록·내부 요소 계층과 접두사 체계
- **상태 · 스크립트** — `data-state` 기반 상태 설계, CSS·JS 역할 분리
- **접근성** — 시맨틱 우선, 최소 ARIA, 키보드 접근
- **미디어 · 성능** — 이미지 역할, 반응형, 로딩 성능
- **경험 설계 (UX)** — 화면 상태, 피드백, 모션, 폼 입력 경험
- **참고** — 접두사 표, 예제, 체크리스트, FAQ

## 문서 구성

문서는 다음과 같이 구성되어 있습니다 ([docs.slur.co.kr](https://docs.slur.co.kr) 사이드바 참고).

- **시작하기** — 개요, 설계 철학, 왜 SLUR인가, 문서 읽는 방법
- **핵심 개념** — UI 구조 모델, 네이밍 시스템, 역할 분리 원칙
- **CSS 방법론** — 블록 규칙, 내부 요소(`i_`), 수정자(`m_`), 중첩 구조, 한 줄 규칙, 토큰, 지양 패턴, 가상 요소
- **JavaScript 및 상태 관리** — 상태 기반 UI, 외부 라이브러리 연동
- **접근성** — 설계 철학, 대체 텍스트, ARIA 최소 사용, 키보드 내비게이션
- **미디어 및 성능** — 이미지 역할, 이미지 다루기, 로딩 성능
- **패턴** — 구조 계층, 팝업/모달, 폼 및 테이블
- **경험 설계 (UX)** — 화면 상태, 피드백, 모션, 폼 입력 경험
- **참고** — 접두사 표, 네이밍 예제, 권장/비권장 사례, 체크리스트, FAQ
- **변경 이력** — 버전 히스토리

---

## 사용 안내

1. 처음 접하는 경우 → `시작하기`부터 읽는 것을 권장합니다.
2. 실무 적용이 목적이라면 → `참고`와 필요한 방법론 섹션을 중심으로 참고하세요.
3. SLUR UX/UI System은 프레임워크가 아닙니다 → 특정 라이브러리나 기술 스택(HTML/CSS, Astro, React, Vue, 정적 마크업)에 종속되지 않습니다.

## 저장소 안내

배포되는 사이트는 **Astro + Starlight**로 빌드됩니다. 주요 명령어:

```bash
npm run dev      # 로컬 개발 서버
npm run build    # 프로덕션 빌드 → dist/
npm run preview  # 빌드된 사이트 미리보기
```

문서 콘텐츠는 `src/content/docs/`에 있습니다. 이 저장소는 방법론의
**문서**이며 코드 라이브러리가 아닙니다.
