# 검토 체크리스트

코드를 작성하거나 리뷰할 때 이 체크리스트를 기준으로 검토한다.

---

## HTML

- [ ] 시맨틱 구조를 사용했는가?
- [ ] 불필요한 태그가 없는가?
- [ ] 네이밍 규칙을 준수했는가? (`p_`, `layout_`, `i_`, `m_`)
- [ ] 상태를 `data-state`로 관리하는가? (클래스로 상태 관리 금지)
- [ ] 버튼과 링크를 올바르게 구분했는가?

## CSS

- [ ] 클래스를 한 줄로 작성했는가? (속성 개수와 무관하게)
- [ ] HTML 구조를 불필요하게 변경하지 않았는가?
- [ ] 선택자 깊이가 3단계 이하인가?
- [ ] 공통 스타일을 재사용했는가?
- [ ] CSS 속성 순서를 준수했는가?
- [ ] 상태 스타일을 `data-state`로 처리했는가?
- [ ] `m_`으로 스타일 변형을 처리했는가?

## JavaScript

- [ ] HTML과 CSS의 역할을 침범하지 않는가?
- [ ] 이벤트를 JavaScript에서 등록했는가? (인라인 이벤트 금지)
- [ ] 상태를 `data-state`로 관리하는가?
- [ ] 컴포넌트 단위로 구조화되었는가?

## 컴포넌트

- [ ] 독립적으로 사용할 수 있는가?
- [ ] 명확한 루트 클래스가 있는가?
- [ ] `i_`, `m_`, `data-state` 규칙을 준수하는가?
- [ ] 내부 요소를 성급하게 독립 컴포넌트로 분리하지 않았는가? (개념적 반복 ≠ 실제 재사용)

## 접근성

- [ ] **페이지에 `h1`이 정확히 하나이고, 그 페이지의 주제인가?** (로고·사이트명을 h1으로 쓰지 않는다)
- [ ] 보이는 제목이 없는 화면에도 `a11y_hidden` h1을 넣었는가?
- [ ] 제목 레벨을 건너뛰지 않았는가?
- [ ] 로고 링크에 이름이 있는가? (`alt` 또는 `a11y_hidden` 텍스트, `alt=""` 금지)
- [ ] 시각 숨김이 `a11y_hidden` 표준 구현인가? (`width:0`/`font-size:0` 방식 금지)
- [ ] 키보드 사용이 가능한가?
- [ ] 버튼과 링크를 올바르게 사용했는가?
- [ ] 이미지에 대체 텍스트(`alt`)가 있는가?
- [ ] 폼 요소에 `label`이 연결되어 있는가?
- [ ] 필요한 `aria-*` 속성을 적용했는가?
- [ ] 초점 이동 순서가 자연스러운가?

## 리팩토링 (기존 코드 이관)

블록 이름만 바꾸고 내부를 남겨두는 **부분 적용**이 가장 흔한 실패다. 아래를 기계적으로 검증한다.

- [ ] `id` 선택자가 0개인가? (CSS·JS 모두. `id`는 `label for`·`aria-*` 연결에만 남긴다)
- [ ] **모든 `layout_` 블록의 내부 요소가 `l_`인가?** (`.layout_header .logo` 같은 잔재 금지)
- [ ] **모든 `page_` 블록의 내부 요소가 `p_`인가?**
- [ ] **모든 팝업이 `modal_`이고 그 내부가 `i_`인가?** (`popup_`·`layer_` 등 구 접두사 0개)
- [ ] 옛 접두사(`sub_` 등)가 전부 사라졌는가?
- [ ] 상태 클래스(`.on` `.current` `.open` `.active` `.fixed` …)가 전부 `data-state`로 갔는가? HTML·CSS·JS 세 곳 모두?
- [ ] CSS 클래스 집합과 HTML 클래스 집합을 대조해 **짝이 없는 이름**을 확인했는가? (변환 전 목록과 비교해 새로 생긴 미아가 없어야 한다)

**전역 치환(sed)으로 안전한 것만 골라 바꾸고 나머지를 미루지 않는다.** `inner_box`·`cont`·`list`처럼 여러 스코프에서 같은 이름이 재사용되는 경우가 반드시 있고, 이건 전역 치환으로 못 바꾼다. 그럴 때는 **부모 블록을 따라가며 문맥별로** 바꾼다(파일 단위 수작업 또는 조상 스코프를 추적하는 스크립트). 도구가 어려워서 규칙 적용 범위를 줄이는 것은 순서가 뒤바뀐 것이다.
