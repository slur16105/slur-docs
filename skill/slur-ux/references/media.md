# 이미지 · 미디어 성능

이미지는 시각 요소가 아니라 **역할을 가진 UI 구성 요소**다. 역할이 명확할수록 대체 텍스트·포맷·로딩 전략이 자동으로 결정된다. 이미지는 반드시 **하나의 역할만** 갖는다.

## 이미지 3역할

- **정보 전달**: 콘텐츠 이해에 필수. 텍스트를 대체/보완. → 의미 있는 `alt` 필수, 품질 우선.
- **기능**: 동작을 유발(버튼·링크·조작 아이콘). → `alt`는 시각 표현이 아니라 **기능**을 서술("검색", "닫기").
- **장식**: 배경·패턴·구분선·의미 없는 아이콘. → 정보를 담지 않는다. `alt=""`(또는 CSS 배경), 용량 최소화 우선.

판단 기준: 없으면 정보가 손실되는가 / 동작의 시작점인가 / 텍스트·구조로 대체 가능한가. 모호하면 설계 단계에서 재검토.

## 포맷 선택

- **WebP**: 대부분의 UI 이미지 기본. JPG/PNG보다 용량 작고 투명도·애니메이션 지원.
- **JPG**: 사진·실사 배경(색상 변화 많고 디테일 중요).
- **PNG**: 투명도가 필요한 아이콘·UI 그래픽(용량 크므로 제한적).
- **AVIF**: 고압축 필요 시 조건부. 브라우저 지원 확인 필수.

역할 매핑: 정보→품질 / 기능→명확성 / 장식→용량 최소화.

`<picture>`로 WebP 우선 제공, 미지원 브라우저용 대체 포맷을 `<img>`에. `width`/`height`는 항상 명시(CLS 방지).

```html
<picture>
  <source srcset="/img/hero.webp" type="image/webp">
  <img src="/img/hero.jpg" alt="봄 신상품 컬렉션 대표 이미지" width="1200" height="800">
</picture>
```

## 반응형

- 실제 **표시 크기 기준**으로 후보 이미지를 제공(디자인이 아닌 구조 기준).
- `srcset`으로 후보를, `sizes`로 표시 폭을 알려 브라우저가 선택하게 한다.
- `width`/`height` 항상 명시. 필요 이상 큰 이미지 금지. 모든 이미지를 반응형 처리할 필요는 없다(장식은 단순 처리).

```html
<img src="/img/card.jpg"
     srcset="/img/card-480.jpg 480w, /img/card-960.jpg 960w"
     sizes="(max-width: 600px) 100vw, 480px"
     alt="상품 카드 썸네일" width="480" height="320">
```

## 로딩 성능

핵심 대비: **초기 화면에 필요한 것은 즉시 로딩(LCP 보호), 나머지는 지연 로딩(lazy).**

- **LCP 대상**(히어로 이미지·첫 화면 대표 블록): `fetchpriority="high"`, 필요하면 `<link rel="preload">`로 앞당김. **지연 로딩 금지** — 최적화 대상이 아니라 보호 대상.
- **그 외**(스크롤 이후·하위 콘텐츠·장식): `loading="lazy"`.
- **두 경우 모두** `width`/`height` 명시 → 레이아웃 이동(CLS) 방지.

```html
<img class="i_thumb" src="/hero.webp" alt="주요 히어로 이미지" width="1200" height="600" fetchpriority="high">
<img class="i_thumb" src="/thumb.webp" alt="하위 콘텐츠 이미지" width="320" height="200" loading="lazy">
```

로딩 전략은 이미지 역할 정의 이후에 결정한다. 성능을 이유로 UX를 해치지 않는다(콘텐츠 지연 체감·CLS 유발 금지). 로딩이 느리면 구조 설계(LCP 요소 등장 위치·불필요한 중첩·상태 변경 후 렌더)를 먼저 점검한다.
