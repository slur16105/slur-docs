# 404 · 오류 페이지

- 모든 웹 프로젝트는 404를 기본 제작한다. 권한 제한·로그인 만료·일시 장애·점검·연결 끊김은 실제 발생 가능한 유형을 검토하고 필요한 화면·복구 경로를 준비한다. 제외 이유를 기록한다.
- 목록·카드 일부 실패는 기존 4상태 블록, 입력 실패는 해당 폼 안에서 해결한다. 전체 페이지를 사용할 수 없을 때 독립 오류 화면. 빈 검색 결과를 404로 표현하지 않는다.
- 공통 구성: 의미 있는 h1 하나 → 현재 상황·해결 설명 → 주요 행동 → 필요한 보조 행동·실제 문의 경로·확인된 점검 시간. 오류 코드는 보조 정보. 규칙만 적용할 때 기존 디자인 유지, slur-design 병행 시 empty_state.m_error 재사용 가능.

| 상황 | 제목 · 설명 출발점 | 행동 |
|---|---|---|
| 404 | 페이지를 찾을 수 없습니다 · 주소를 확인하고 홈이나 목록에서 다시 찾아 주세요 | 홈 / 관련 목록. 같은 URL 재시도를 해결책으로 삼지 않음 |
| 권한 제한 | 이 페이지에 접근할 권한이 없습니다 · 현재 계정으로는 볼 수 없습니다 | 접근 가능한 홈 / 실제 권한 요청 / 계정 전환 |
| 세션 만료 | 다시 로그인해 주세요 · 로그인 정보가 만료되었습니다 | 로그인 후 허용된 내부 경로 복귀. 단순 미로그인은 “로그인이 필요합니다” |
| 일시 장애 | 일시적으로 페이지를 불러오지 못했습니다 · 잠시 후 다시 시도해 주세요 | 안전한 조회 재시도 / 작동하는 홈·실제 문의 |
| 점검 | 서비스 점검 중입니다 · 점검이 끝난 뒤 다시 이용해 주세요 | 실제 점검 공지 / 작동하는 홈 / 사용자 요청 재시도. 시간은 확인된 경우만 |
| 연결 끊김 | 인터넷 연결을 확인해 주세요 · 연결 상태를 확인한 뒤 다시 시도해 주세요 | 재시도 / 실제 제공하는 저장 콘텐츠 |

- 목적지·문의 경로가 없으면 버튼과 해당 문구도 제거·조정한다. 확인하지 않은 원인·복구 시간·입력 보존을 약속하지 않는다. 보호된 리소스·계정 정보는 노출하지 않고, 존재 여부를 숨겨야 하면 보안 정책에 따라 404 안내를 사용한다.
- 이동은 a, 재요청은 button. 뒤로 가기만 제공하지 않고 명시적인 안전한 홈/목록 링크를 둔다. history.length만으로 안전한 이전 화면을 판단하지 않는다. 자동 강제 이동 금지.
- 재시도: 진행 중 표시·중복 실행 방지 → 성공 시 정상 복귀 / 재실패 안내와 대안 유지. 자동 무한 재시도 금지. 결제·저장·등록은 처리 결과 확인·중복 방지 없이 재전송하지 않는다. 가능한 입력·맥락 보존.
- 로그인 복귀 주소는 검증된 내부 경로만. 오류 화면은 장애 난 API·인증 초기화에 의존하지 않도록 최소 셸을 준비한다. JS·외부 이미지·폰트 없이도 핵심 안내·이동 링크 제공.
- 고유 title·main·h1. 동적 전체 화면 전환은 title 갱신·새 제목(tabindex=-1) 초점 이동. 최초 문서 로드 초점 강탈 금지. 재시도 결과는 미리 존재하는 role=status에서 알리고 초점 유지. 정적 오류 페이지에 4상태·role=alert를 강제하지 않음.
- 운영의 잘못된 URL은 실제 404 응답과 화면으로 연결한다. 홈 강제 리디렉션·200 정상 응답으로 숨기지 않는다. 서버 오류·점검은 원인에 맞는 상태 코드, 503 복구 시점을 알면 Retry-After. UI 조립본은 호스팅/SPA 라우팅·상태 코드 설정을 대체하지 않는다.
- 검증: 존재하지 않는 하위 URL 직접 진입·실제 응답 코드, 방문 기록 없는 진입, 모든 목적지, 재시도 중복·실패·복구 성공, 인증 복귀, 입력 보존, 키보드/초점/상태 안내, 320px·확대·라이트/다크, JS·외부 자산 미로드, 점검 해제 후 복귀를 확인한다. 예제의 모의 동작과 운영 검증은 구분해 기록한다.
