# 모바일 헤더 기준

메뉴가 있다는 이유만으로 고정하지 않는다. 콘텐츠를 보는 도중 메뉴를 반복적으로 사용할 필요가 있는지 판단한다.

## 방식 선택

| 화면 맥락 | 권장 방식 |
|---|---|
| 읽기에 집중하며 메뉴 사용이 드묾 | 콘텐츠와 함께 스크롤 |
| 콘텐츠 탐색 중 메뉴로 자주 이동 | 아래로 스크롤하면 숨김, 위로 스크롤하면 재노출 |
| 현재 단계나 조작이 계속 필요 | 필요한 최소 영역 고정 |
| 검색·필터를 반복 사용 | 필요한 컨트롤만 고정하는 방식 고려 |

## 숨김·재노출 동작

- 최상단에서는 표시하고, 아래로 스크롤해 헤더 영역을 지나면 숨긴다. 위로 일정 거리 이상 스크롤하면 상단에 도달하기 전에도 표시한다.
- 미세한 움직임·스크롤 튕김에 반응하지 않는다. 위로 스크롤하는 것은 앞선 내용을 다시 읽으려는 행동일 수도 있으므로 재노출 거리와 전환 속도는 실제 화면에서 정한다.
- 표시·숨김으로 본문 위치가 밀리거나 튀지 않게 한다. 헤더 높이와 로고 크기는 유지한다.
- 메뉴가 열렸거나 헤더 내부에 키보드 포커스가 있는 등 상호작용 중에는 숨기지 않는다.
- 전환은 짧고 절제하며 동작 줄이기 설정을 존중한다.

## 크기

수치는 SLUR의 초기 기본값이며 실제 화면에서 검증하며 조정한다.

- 기본 높이 **56px**, 브랜드 표현이나 기능상 이유가 있을 때 **64px까지** 확장한다. 상단 안전 영역은 별도로 확보한다.
- 로고 권장 높이 **24px**, 최대 높이는 **헤더 높이 − 24px, 단 32px 이하**다. 최대값은 목표 크기가 아니다.
- 로고 원본 비율을 유지하고 가용 너비도 제한해 메뉴·버튼 영역 침범을 막는다. 불필요한 투명 여백을 정리하고 시각적 크기를 확인한다.
- 메뉴 등 버튼 터치 영역은 **최소 48 × 48px**로 확보한다. 아이콘의 시각적 크기와 구분한다.
- 검색창이나 추가 탐색 행은 기본 헤더를 임의로 늘리지 않고 별도 영역으로 구성한다.

## 확인

작은 화면의 콘텐츠 가림, 재노출에 의한 읽기 방해, 키보드·하단 고정 요소 충돌을 확인한다. 저장·완료처럼 계속 필요한 조작은 숨겨지는 헤더에만 의존하지 않는다.
